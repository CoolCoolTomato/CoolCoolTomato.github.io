使用指针的优势

  • 节省内存，提高性能（减少数据复制带来的开销）
  • 能够直接修改变量的值（函数传递等）
  • 用于构建链表和树等数据结构
  • 优化内存管理管理（将指针设为nil，使对象可被垃圾回收）

值类型和引用类型

  • 值类型直接储存值，内存通常在栈上分配
  • 引用类型储存的是一个地址，内存通常在堆上分配，通过GC回收

指针和引用的区别

严格来说go没有引用类型，例如map 底层是一个指向 hmap 的指针，这就可以解释即使函数传参是按值传递，由于传递的是指针的拷贝，指针指向的底层 hmap 并没有改变，所以可以在函数内部改变 map

  • 引用是变量的别名，通过引用可以直接操控变量本身（快捷方式）
  • 指针储存一个内存地址

如何知道一个对象是分配在栈上还是堆上

如果编译器能证明一个变量的生命周期不会超过当前栈帧，并且适合栈上分配，那么它通常会分配在栈上。即能证明不会逃逸：栈上分配或直接优化掉。

如果变量可能在函数返回后仍被访问，或者编译器无法证明其不会逃逸，则可能分配到堆上。

  1. 被 goroutine 闭包引用，通常逃逸。

函数返回局部变量的指针是否安全

在Go里面返回局部变量的指针是安全的。因为Go会进行逃逸分析，如果发现局部变量的作用域超过该函数则会把指针分配到堆区，避免内存泄漏。

非接口的任意类型 T() 都能够调用 *T 的方法吗？反过来呢？

Go 规范里规定：T 的方法集只包含 receiver 为 T 的方法；*T 的方法集同时包含 receiver 为 T 和 *T 的方法。

当 T 类型的值是可取地址的，可以调用*T 的方法。 这是 Go 的语法糖：如果 x 可取地址，并且 &x 的方法集中有这个方法，那么 x.m() 会被当成 (&x).m()。

无缓冲的 channel 和有缓冲的 channel 的区别

无缓冲区channel： 发送的数据如果没有被接收方接收，那么发送方阻塞。 如果一直接收不到发送方的数据，接收方阻塞。

有缓冲的channel： 发送方在缓冲区满的时候阻塞，接收方不阻塞。 接收方在缓冲区为空的时候阻塞，发送方不阻塞。

讲讲go的协程泄露

Go 的“协程泄露”更准确地说是 goroutine 泄露：某个 goroutine 被创建后，本来应该结束，但因为一直阻塞、等待、循环或无法收到退出信号，导致它长期存活，无法被 GC 回收。

注意：goroutine 本身不是内存对象泄露，但 goroutine 持有栈、引用、channel、连接、锁等资源，所以最终会造成内存上涨、CPU 异常、连接耗尽、服务卡死。

主要原因有：

  1. channel 读阻塞

这个 goroutine 会一直等 ch 里有数据。

如果后续永远没人写入，goroutine 就泄露了。

  1. channel 写阻塞

无缓冲 channel 写入时，必须有接收方。

如果没人接收，写入方会永久阻塞。

  1. for range channel 但 channel 没有关闭

for range ch 只有在 channel 被关闭后才会退出。

如果发送方不再发送数据，但也不关闭 channel，那么 worker 会一直阻塞。

  1. 没有退出条件的后台 goroutine

rune和byte有什么区别

类型不同：

  • byte：字节，是uint8的别名类型
  • rune：字符，是int32的别名类型

储存的字符不同：

  • byte用于表示ASCII码字符，0-255
  • rune用于表示Unicode字符，可以储存任意Unicode字符

占用的字节大小不同

  • byte：1
  • rune：4

字符串

八位字节集合，可为空，不为nil，本质上是一个byte类型数组，不可变，并发安全，每次修改字符串都需要重新分配内存。之前的空间会被回收。

拼接方式：

排序： jion = builder > buffer > []byte转换string > + >fmt.sprintf

  • builder会预分配空间，减少扩容，效率更高，适合长字符串操作
  • buffer主要用于处理单个字符，可以针对单个byte进行删除替换操作

数组和切片的区别

  • 数组定长，切片大小可变，自动扩容
  • 作为函数参数，数组传值，切片传引用

切片扩容/缩容

1.18版本：

  • 添加元素容量不足触发扩容，分配一个新的数组，小于1024扩容1倍，大于1024扩容1/4倍
  • 删除元素时切片长度小于容量的1/4触发缩容，分配一个新的数组，小于1024长度不变，大于1024缩容1/2。

大于 1.18 版本：

  • 添加元素容量不足触发扩容，分配新的底层数组；如果一次 append 后的新长度大于旧容量的 2 倍，则新容量直接取新长度。
  • 如果旧容量小于 256，则新容量按 2 倍扩容。
  • 如果旧容量大于等于 256，则进入平滑扩容阶段，通过 newcap += (newcap + 3*256) >> 2 逐步增长，扩容倍率会从 2 倍逐渐过渡到约 1.25 倍。
  • 实际最终容量还会受元素大小和内存分配器 size class 影响，因此最终 cap 不一定严格等于上述计算值。
  • 删除元素不会自动触发缩容；切片缩短长度只会改变 slice header 的 len，不会主动释放或缩小底层数组。需要手动 copy 到新切片，或使用 slices.Clip 等方式主动裁剪容量。

浅拷贝与深拷贝

  • 值类型每次拷贝都会申请一块新的地址
  • 引用类型浅拷贝只拷贝指针的指向（地址），深拷贝会申请一块新的地址

make和new有什么区别

  • new给任意类型分配地址，初始化零值，返回指针
  • make用于创建并初始化引用类型的变量，如slice、channel，map，返回引用

在 for range 循环中，变量的地址会发生变化吗

这个问题的答案取决于使用的 Go 版本。

  • Go 1.21 及之前：循环变量在内存中只有一份。每次迭代都会将新值覆盖写入这同一块内存，因此它们的地址在循环中始终不变。
  • Go 1.22 开始：语言语义得到了优化。现在，每次迭代都会创建全新的循环变量，拥有独立的地址。

init() 函数是什么时候执行的

在main函数之前执行。init()函数是go初始化的一部分，由runtime初始化每个导入的包，初始化不是按照从上到下的导入顺序，而是按照解析的依赖关系，没有依赖的包最先初始化。

每个包首先初始化包作用域的常量和变量（常量优先于变量），然后执行包的init()函数。同一个包，甚至是同一个源文件可以有多个init()函数。

init()函数没有入参和返回值，不能被其他函数调用，同一个包内多个init()函数的执行顺序不作保证。

执行顺序：import –> const –> var –>init()–>main()

一个文件可以有多个init()函数！

defer 在什么时机会修改返回值

defer 延迟函数，释放资源，收尾工作；如释放锁，关闭文件，关闭链接；捕获 panic。

修改返回值时机：defer 会在返回值赋值完成后、函数真正返回前执行。因此它可以修改有名返回值，也可以修改返回指针、slice、map 等引用对象指向的内容；但对于普通无名返回值，return 表达式的结果已经被拷贝，defer 通常无法再改变最终返回值。

  • 数组/切片越界
  • 空指针调用
  • 过早关闭 HTTP 响应体
  • 除以 0

  • 重复关闭 channel
  • 关闭未初始化的 channel

Map是并发安全的吗

Map不是并发安全

  • 手动加读写锁
  • 使用sync.Map

Map的key删除后内存会释放吗

  • value为值类型，则map的内存不会自动释放
  • value为引用类型，则map的内存会自动释放
  • map设为nil，内存回收

Map产生的panic能被recover吗

Map 由于并发读写导致的 panic 是不能被 recover 的，因为 Map 的异常使用 runtime.throw() 抛出，这类异常不能被 recover。

泛型和接口有什么区别

  • 接口是在运行时实现的，泛型是在编译时实现的，泛型在编译时会编译成具体的类型，所以泛型性能更好
  • 接口主要用来约束方法，用于定义对象的行为，泛型主要用来约束类型，让代码可以处理多种类型
  • 接口是go语言的原生特性，泛型是1.18版本引入
  • 泛型引发的错误在编译时能发现，而接口在运行时才能发现

其它

  • 对未初始化的Map赋值会引发panic
  • 对未初始化的Map删除会引发Panic（早期版本，现版本不会）
  • 对未初始化的Map读取key会返回当前类型的空值
  • 执行for range时遍历的是副本
  • defer执行顺序先进后出
  • Map 会自动扩容，但是不会自动缩容。
  • channel 是线程安全的，原因是 channel 内部实现了锁的机制
  • Map 在内部使用哈希算法放置元素，在自动扩容时又会重新计算哈希值，因此元素的地址会不断变化，官方为了避免用户认为 Map 元素排列是有序的，直接采用随机顺序返回，所以遍历是无序的
